# 餐饮短视频拆片与仿拍结构

## 任务

把一条餐饮参考视频转换为独立、可复用、可交给餐饮客户执行的拆片文档。核心工作是解释“这条片为什么这样成立、服务哪个消费场景、复刻时必须保留什么”，不是把画面机械地写成镜头清单。

## 适用输入

- 本地可读取的视频文件，优先使用完整的 MP4、MOV 或同类文件。
- 可选的口播、字幕、画面文案或用户补充的内容说明。
- 可选的拆片模板。模板只决定版式，不替当前视频补事实。
- 可选的门店事实、产品信息和发布目标。缺失时降低结论强度，不自行补造。

如果输入文件无法解码，先检查同一目录是否有同名的完整视频；不要修改原片，也不要把 `.part` 文件名当成已完成素材。只有拿到可读取的素材后才进入内容判断。

开始输出前记录来源标签、文件名、素材是否完整、采用的音频／字幕来源和抽帧或转写工具。内部测试可保存哈希和工具版本；对外分享的结果只保留不泄露本机路径和隐私的来源说明。

按需读取：需要固定版式时读取 [`references/output-template.md`](references/output-template.md)；需要判断素材模式、证据层级或低工具环境时读取 [`references/modes-and-evidence.md`](references/modes-and-evidence.md)；需要设计内测样本或评分时读取 [`references/evaluation-rubric.md`](references/evaluation-rubric.md)。

## 核心不变量

1. **先判断，再拆时间线。** 时间线之前必须写清消费场景、视频任务、内容主线、核心到店理由和复刻核心。
2. **一条视频一份独立结果。** 不引用其他视频的内容、结论或关键帧；模板中的旧内容只作格式参考。
3. **分开证据层。** 明确区分画面可见事实、可听见或可读出的口播／字幕、用户提供的表达、分析推断和需要验证的经营事实。
4. **内容任务和分发角色分开。** 流量、食欲种草、转化和多轮触达是视频任务；蓝 V、达人、主页和团购页是分发或承接位置，不能混为内容类型。
5. **不把一环写成全链路。** 说明视频在“种草→主页理解→团购→到店理由→核销→服务→评价／复购”的哪一段发挥作用；不得把播放、售券或画面好看写成到店、核销或成交。
6. **复刻提供抓手，不锁死参数。** 给出动作、证据、顺序、替换变量和可选方案；不要固定灯光、机位、角度、距离、焦段、运镜速度或现场效果。
7. **尊重模板留空约定。** 使用用户确认过的模板时，原片视频位置和前置高亮块位置留空，由用户自行贴入；关键帧放在对应的逐段拆片中。除非用户明确要求，不代贴原片。
8. **不承诺平台结果。** “有流量”“让人想吃”“愿意到店”只能作为结构目标或待测假设，不能由拆片直接证明。

## 工作流程

### 1. 先核对素材和可见证据

记录时长、画幅、分辨率、横竖屏、镜头切换或连续素材特征，以及是否存在音频、口播、字幕和画面文字。用抽帧、波形、转写或字幕识别取得底层材料；工具结果用于定位，不代替内容判断。

如果口播决定了叙事，必须把口播和画面放在同一条时间线上；不能只看画面猜故事。

### 2. 建立前置判断卡

在逐段拆解前输出以下字段：

- **消费场景**：谁在什么时间、和谁、因为什么需求到店；例如下班后独食小酌、久别朋友夜间聚会、夏夜朋友聚餐。
- **视频任务**：选择一个主任务，可补充次任务：流量注意、食欲种草、到店转化、多轮触达或其他明确目标。
- **内容主线**：用一句话写清从开头到结尾的变化或证据顺序，不写菜品名流水账。
- **核心到店理由**：为什么是这家店、为什么适合这个人群、为什么可能在这个时间发生；如果素材没有给出，明确写缺口。
- **复刻核心**：客户需要保留的关系、场景、证据和情绪机制；同时写出可以替换的产品、人物、地点和动作。
- **承接位置**：这条片应该由主页、团购页、常态触达或到店服务中的哪一步承接；没有证据时写成待验证建议。

### 3. 选择拆解模式

- **视觉主线型**：画面动作和节奏承担主要叙事，逐段说明每个画面如何推进主线。
- **口播主线型**：口播提出理由或观点，画面逐项提供证据；逐句对齐口播和画面功能。
- **连续现场型**：素材没有明显切镜头，重点拆人物关系、空间氛围、共同动作和文案承担的故事。
- **文案主线型**：动图或连续画面本身信息有限，用户提供的文案承担关系和情绪推进；把文案作为表达层，不写成已核实事实。

模式选择按“谁承担理解任务”决定：口播或字幕决定观众如何理解时优先口播主线型；连续画面本身信息不足而用户文案提供故事时优先文案主线型；没有明显语音或文案、画面动作能独立推进时用视觉主线型；镜头切换少且重点是关系和现场感时用连续现场型。可以组合模式，但要说明谁在承担叙事、谁在提供证据。

如果音频无法转写，先使用烧录字幕、用户提供的逐字稿或人工可辨识的短句；三者都没有时，不猜口播，只做视觉层拆片并标记“口播未验证”。

### 4. 做逐段证据链

每一段至少写清：

| 字段 | 要回答的问题 |
| --- | --- |
| 时间 | 这一段从哪里开始，到哪里结束？ |
| 关键帧 | 哪一帧能证明这段功能？关键帧放在逐段拆片，不放进原片占位区。 |
| 画面／声音 | 观众实际看见、听见或读到了什么？ |
| 功能 | 注意、场景、产品、口感、关系、服务、到店理由还是行动承接？ |
| 证据 | 这一段具体证明了主线中的哪一件事？ |
| 复刻抓手 | 客户需要完成什么动作或准备什么替代素材？ |
| 边界 | 哪些是观察，哪些是推断，哪些还要验证？ |

不要把“拍产品特写”当成完整抓手。要写出它在整条证据链中的作用，例如证明鲜货、放松氛围、多人关系或某个具体消费时机。

### 5. 提炼客户可拍脚本

把逐段证据链转换成可执行样片：

```text
目标效果 → 最小动作 → 需要留下的证据 → 可替换变量 → 可选替代镜头
```

脚本应告诉客户“拍什么、为了证明什么、前后如何衔接”，不替客户决定现场唯一正确的灯光和机位。需要时给两到三个替代动作，保留现场调整空间。

### 6. 输出独立文档并自检

默认结构为：

1. 消费场景
2. 视频任务
3. 内容主线
4. 核心到店理由
5. 复刻核心
6. 逐段拆片与关键帧
7. 客户可拍样片脚本
8. 事实、推断和待验证项
9. 适合的承接位置

交付前检查：前置判断是否先于时间线；每条关键帧是否在正确段落；原片和前置高亮位置是否留空；是否出现其他视频内容；口播和画面是否对齐；是否把用户文案或分析推断冒充经营事实；是否出现固定拍摄参数或平台结果承诺；来源标签、素材完整性和工具限制是否写清。时间码使用素材播放器或探针的同一时基，短片至少精确到 0.1 秒；连续现场无法精确切段时标注“约”，不要伪造帧级精度。

## 需要暂停或收窄的情况

- 视频无法读取，且同目录没有可用完整文件。
- 用户要求的结论依赖门店真实销量、平台流量、核销或客户反馈，但当前没有来源。
- 输入只有菜品照片或模糊描述，无法判断视频结构；可以改为素材策划，不冒充拆片。
- 用户要求保证流量、成交或核销结果；改为输出待测结构假设和验证指标。
- 用户要求把其他视频的结论、客户信息或私密资料复制进本条文档；保持每条视频独立并拒绝越界。

## 外部写入边界

默认只输出拆片结果或本地草稿。写入飞书、上传图片、发布 Skill、创建仓库或发送给他人，必须以用户当前明确授权为准；即使完成了文档写入，也要把“拆片完成、客户验收、平台发布、商业结果”分开记录。

## 当前内测状态

这是内测版。方法来源于氛围蒙太奇、连续现场动图和口播加画面三类真实样片，但样片和客户资料不随 Skill 发布，测试者需要提供自己的素材。尚未完成独立留出样本、跨环境安装和国内 Agent 兼容测试。发现稳定失败时，优先修改判断条件、输出边界或验收规则，不为单个视频增加特例。
